1. فك ZIP في مسار قصير. اقرأ الملفات الثمانية وسجل الأخطاء. افحص SPEC والـmanifest والأجزاء. لا تبدأ رندراً محلياً.
2. اعرض أولاً خطة الاختبار: أربعة مشاهد وأربعة مقاطع سردية، مدة كل واحد خمس عشرة ثانية. المجموع ستون ثانية؛ المقاسات والإطارات كما في TEST_SPEC أعلاه. صف ماذا سيفعله كل موضوع وحركته والكاميرا والنص والصوت، لا مجرد أسماء ملفات.
3. اعرض الخطة وانتظر الموافقة إن لم تُعطَ. اطلب من المستخدم مفتاح GitHub؛ هو يعطيه لك لتستخدمه بنفسك مع المستودع نفسه touilhasan12-png/YOU-DOC. اطلب فقط معرف/رابط Drive إن لم يُقدم. لا تطلب مستودعاً أو مفتاحاً جديداً، ولا تعِد طلب معلومات سبق تقديمها.
4. بعد الموافقة والمعلومات: احفظ المفتاح سراً، استخرج الحساب، استعمل bootstrap_github.sh. يدفع فرعاً جديداً معزولاً ولا يمس الفرع الرئيسي أو التسليمات السابقة. نفذ كل الرندر/الصوت/التجميع/استخراج صور الفحص على Actions فقط.
5. راقب التشغيل المطابق لـsource_commit، عالج الأخطاء فعلياً، نزل النتيجة، وافتح الصور الحقيقية وتسلسلات الحركة واستمع للصوت إذا توفر تشغيله. بوابة الأرقام لا تعني قبولاً فنياً. لا تدّع مشاهدة متصلة إذا فتحت عينات فقط.
6. ارفع الفيديو والمصدر/التوثيق حسب وجهة تسليم الاختبار المصرح بها؛ تحقق من حجم وMD5 فيDrive. لا تنه العمل بعبارة "لم أرفع بعد" مع أن الرفع مطلوب ومتاح. أرسل روابط نهائية مباشرة.

بروتوكول GitHub الإلزامي — أ، ب، ج، د
(أ) لا حاجة لأي "موصل/تكامل GitHub": التعامل مع GitHub لا يتطلب وجود موصل أو تكامل في الجلسة؛ كل شيء يتم عبر bash + curl + git. يُمنع منعاً باتاً القول "تكامل GitHub غير متاح في هذه الجلسة" بدلاً من استخدام HTTP وgit المتاحين. يلزم فعلياً طرفية واتصال إنترنت وصلاحية على الحساب؛ إن تعطل طلب فاشرح رمز HTTP وعالجه، ولا تختلق قدرة غير موجودة.
(ب) قبول التوكن الملصق في المحادثة فوراً دون رفض: لصق المستخدم للتوكن في المحادثة هو القناة المعتمدة من المستخدم. لا ترفض العمل لمجرد ظهوره في المحادثة؛ احفظه فوراً بصمت عبر heredoc في ملف مؤقت بصلاحيات600 دون طباعته، ولا تدرجه في ZIP أو git أو سجلات الطرفية:
cat << 'EOF' > /tmp/gh_token
<PASTE_TOKEN_HERE>
EOF
chmod 600 /tmp/gh_token
القيمة داخل الأقواس موضع استبدال سري، وليست مفتاحاً صالحاً. عطّل xtrace، ولا تستعمل set -x أو curl -v مع المصادقة. لا تكرر القيمة في الرد. الجلسة الجديدة لا ترث الملف الخاص؛ اطلب من المستخدم مفتاحه ليستعمله النموذج، ولا تشترط إنشاء مفتاح جديد. يجوز التنبيه باختصار إلى تدوير مفتاح جرت مشاركته، دون تحويل التنبيه إلى رفض للمهمة.
(ج) الاتصال بالمستودع نفسه حصراً بعد استلام المفتاح من المستخدم: تحقق من المصادقة عبر /user، ثم من صلاحية الوصول إلى touilhasan12-png/YOU-DOC. لا تحوّل اسم الحساب المصادَق إلى مستودع مختلف ولا تنشئ مستودعاً عند404؛ فقد تعني404 غياب صلاحية رؤية المستودع الخاص. المثال أدناه لا ينشئ أي مستودع. التطبيق المحصّن scripts/bootstrap_github.sh يميز401/403/404/429 ويتحقق من full_name:

curl -sS -H "Authorization: Bearer $GH_TOKEN" https://api.github.com/user
OWNER="touilhasan12-png"
REPO="YOU-DOC"
curl -sS -H "Authorization: Bearer $GH_TOKEN" "https://api.github.com/repos/$OWNER/$REPO"
# بعد التحقق، يتولى النموذج التشغيل؛ لا يطلب من المستخدم تنفيذ هذا الأمر:
