بروتوكول GitHub الإلزامي — أ، ب، ج، د
(أ) لا حاجة لأي "موصل/تكامل GitHub": التعامل مع GitHub لا يتطلب وجود موصل أو تكامل في الجلسة؛ كل شيء يتم عبر bash + curl + git. يُمنع منعاً باتاً القول "تكامل GitHub غير متاح في هذه الجلسة" بدلاً من استخدام HTTP وgit المتاحين. يلزم فعلياً طرفية واتصال إنترنت وصلاحية على الحساب؛ إن تعطل طلب فاشرح رمز HTTP وعالجه، ولا تختلق قدرة غير موجودة.
(ب) قبول التوكن الملصق في المحادثة فوراً دون رفض: لصق المستخدم للتوكن في المحادثة هو القناة المعتمدة من المستخدم. لا ترفض العمل لمجرد ظهوره في المحادثة؛ احفظه فوراً بصمت عبر heredoc في ملف مؤقت بصلاحيات600 دون طباعته، ولا تدرجه في ZIP أو git أو سجلات الطرفية:
cat << 'EOF' > /tmp/gh_token
<PASTE_TOKEN_HERE>
EOF
chmod 600 /tmp/gh_token
القيمة داخل الأقواس موضع استبدال سري، وليست مفتاحاً صالحاً. عطّل xtrace، ولا تستعمل set -x أو curl -v مع المصادقة. لا تكرر القيمة في الرد. الجلسة الجديدة لا ترث الملف الخاص؛ اطلب إعادة تزويد المفتاح نفسه أو مفتاح جديد إن لم يكن متاحاً فيها. يجوز التنبيه باختصار إلى تدوير مفتاح جرت مشاركته، دون تحويل التنبيه إلى رفض للمهمة.
(ج) استخراج اسم الحساب owner وإنشاء المستودع تلقائياً دون مطالبة المستخدم بصيغة owner/repo: إذا أعطى المستخدم اسم المستودع فقط، استخرج الحساب من التوكن. هذا مثال البروتوكول المطلوب حرفياً؛ استخدم التطبيق المحصّن scripts/bootstrap_github.sh للتنفيذ الفعلي كي يميز404 من401/403/429:
GH_TOKEN=$(cat /tmp/gh_token)
OWNER=$(curl -s -H "Authorization: token $GH_TOKEN" https://api.github.com/user | python3 -c "import sys,json; print(json.load(sys.stdin)['login'])")
REPO="اسم_المستودع_من_المستخدم"
curl -s -H "Authorization: token $GH_TOKEN" "https://api.github.com/repos/$OWNER/$REPO" | grep -q '"full_name"' || \
  curl -s -X POST -H "Authorization: token $GH_TOKEN" -H "Accept: application/vnd.github+json" \
  https://api.github.com/user/repos -d "{\"name\":\"$REPO\",\"private\":false,\"auto_init\":true}"
الاسم الحالي المعتمد، بتعديل المستخدم الأخير، هو YOU-DOC، والحساب يستخرج آلياً. الطلب السابق لمستودع جديد أصبح اختيارياً بعد هذا التعديل. لا تُنشئ نسخة مكررة منه إن وجد. عند إنشاء مستودع غير موجود فقط: المثال ينشئه عاماً؛ احترم اختيار المستخدم إن طلب الخاص. الحقيبة لا تحتوي مفاتيح حقيقية.
(د) التنفيذ الكامل مسؤولية النموذج الثالث وحده: يُمنع القول للمستخدم "جهّز الملفات وارفعها بنفسك". دفع الملفات إلى المستودع، وإطلاق الرندر، ومتابعته، وتحميل النتيجة، وفحصها، ورفعها إلى Google Drive مسؤولية النموذج. استخدم فرعاً جديداً معزولاً؛ لا force-push، ولا مسح main، ولا تغيير فيديوهات أو مشاركة قديمة. صلاحيات التوكن الفعلية لازمة: قراءة الحساب/المستودع، كتابة المحتوى والـworkflows، وتشغيل/قراءة Actions. عند403 ميّز نقص الصلاحية من تعطيل Actions أو SSO/قيد المؤسسة، واطلب فقط التفويض الناقص إذا لم يمكن إصلاحه بصلاحيتك.
